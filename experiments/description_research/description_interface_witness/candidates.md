# 候选、生产问题和选题边界（文献与决策整理，不主张已建立新颖性）

候选和原始资料在首轮描述调用前已调查；本说明整理于冻结运行期间，不能称这份说明本身已事前冻结。事前协议与哈希以 protocol.json 和 freeze.json 为准。

本轮只研究有源码依据的功能、模块及实现描述。三个停止的旧路线、比较/同源/抄袭/公共上游研究均排除。本目录没有恢复旧实验代码，没有行为图、条件单元、状态卡、条件 JSON 或摘要局部修复。

## 生产链核实

`cli/agent.py::_run_tree_mode` 先采集 `analysis/repo_facts.py`，然后 `pipeline/tree_builder.py::build_tree` 枚举子系统、逐子系统生成、总评、语言护栏，交由 `reports/html_tree.py` 和 `finals/digests.py`；后者生成短 digest 供 `finals/summary_pdf.py`。`finals/readability.py` 有限长与纯文本/HTML 清理；既有修复保留。当前 `finals/integrity.py::collect_integrity_facts` **仅返回硬编码扫描**，不运行构建，不能沿用旧 README 的构建/可用性说法。

枚举跳过 vendor/tests 等范围，按内容指纹或路径单一分组。提示文件按目录/语言轮流取样，默认最多80个；工具读取上限12次。`read_file` 默认只返回头80行、尾40行，显式范围最多200行。模块只需1–4个代表文件；`_validate_repo_location` 只验证存在、仓库边界与行范围，不能核实陈述。`_clean_tree` 删除输入文件清单，旧报告也没有实际阅读轨迹。现有完整文本/引用保留和字体、取样、运行日志、浅克隆工程修复均不撤回。

分类：源码理解错误需独立语义参考；未分析范围与模块遗漏需要覆盖参考；引用位置存在不等于依据充分；展示破坏属于已有确定性回归。不能用后一类的测试通过率支持前三类研究效果。没有可用的正式比赛报告集，本轮自然源码上的读取缺口由 prepared/ 和 references/ 中的定位与实际工具输出复现，不能当比赛总体失败率。

## 三个实质不同的问题

| 候选 | 改善步骤、真实缺口、评委用途 | 最近工作与潜在差异 | 独立参考、难度与成本 | 选择 |
|---|---|---|---|---|
| A：按评审信息需求分配模块阅读预算 | 源码选取/模块拆分；80个候选及少数代表文件没有覆盖约束；帮助判断哪些主要模块仍需人工查看 | CodeWiki 的特征模块分解与层级 rubrics、RepoAgent 的仓库依赖上下文已经接近。新增一般覆盖优化/多Agent不构成新颖性；需首先建立自然模块遗漏数据 | 模块边界/重要性缺少自动独立真值；官方文档可能不对应实现。跨仓库特征参考和评委需求研究成本高 | 不作为首轮算法；保留明确索引/提示/代表来源的工程显示 |
| B：以接口注册位置保留描述的实现归属 | 实现描述的源码取证；操作表把字段绑定到函数，默认头尾读取可漏表；函数组件库存不能直接代替模块接口。评委需要核对“哪个模块的哪一项操作由何处承接” | DocAgent/CodeWiki/ASAP 已做语义上下文，静态绑定分析与符号查找也是既有技术。仅保留注册单元能否带来超出简单查表的收益是待证伪问题，不能宣布空白 | 原始 C designated initializer 可投影编译执行得到有限绑定参考，Ctags 独立定位函数；不用编译OS。少量源码+约36次请求、<180k token | 选作最低成本机制检验；直接查表是强基线，持平则淘汰论文方法主张 |
| C：检验引用对具体实现陈述的充分性 | 引用/交付门禁；有效path:line只能排除虚构位置，旧工程材料有无依据smoltcp/ENOSYS扩写记录；帮助评委判断某陈述是否真正由该位置支持 | ReFEree 已用分段事实核验和依赖上下文；METAMON 已用执行/文档一致性。用模型互评、再拆断言或反例修复属于旧路线或已有方法直接拼装 | 任意自然陈述缺少独立真值；编译/执行只验证窄事实，不能评价所有职责/算法说明。人工金标或受限断言集合不可省略，第一轮成本高 | 排除普通LLM核验器拼装；B中只检查可审计的双位置，不扩成通用事实核验论文 |

B 的候选是研究问题的有限可证伪检验，尚不是满足 TSE/TOSEM 新颖性要求的新算法。若简单检索已经覆盖全部机制，不能把工程注册表支持改名当论文贡献。当前最充分证据是生产读取缺口和可自动取得的有限参考，不是未经验证的论文前景。

- [ReFEree, ACL 2026 原文](https://aclanthology.org/2026.acl-long.653/)及[论文给出的官方实现](https://github.com/bsy99615/ReFEree)：已研究细粒度一致性与选取依赖上下文；评价数据为 Python/Java，非本轮 C 静态绑定独立参考。下载PDF并核对源代码链接，避免误用同名雷达项目。

## 独立参考能支持什么

参考把原操作表的显式标识符赋值投影到最小C结构，保留每条原赋值；GCC编译后，通过函数地址实际比较输出字段绑定，两次一致。它执行投影，不执行内核。函数定义范围由独立 Universal Ctags 提供；候选由 tree-sitter 提取。字符串字段/嵌套表/动态注册/配置裁剪不进入本任务的绑定分母，因此不能推断完整接口支持率。源码污染和同系列代码相似性没有被排除，仓库是3个而不是33个独立绑定样本。

描述生成只接收真实源码，不接收编译参考答案。返回JSON仅是描述传输格式，不是条件记录或后续短摘要输入。职责中文保留供审阅；自动结果只核验名字绑定和引用来源，不能称全文语义正确率或评委效率。
