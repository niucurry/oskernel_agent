两个仓库的候选/简单基线输入完全相同，四个方法格按协议共用回复。Mynewt输入有170字节差异，两轮均持平。所有候选及强基线输出均未超预算。主假设要求开发两轮相对**最强基线**至少提高10个百分点；实际零增益，两个确认仓库也没有增益。相对BM25或组件适配的优势不够成为研究贡献。没有事后改提示或换样本挽救。

生产适配的一次输出使用 `_dev_fops.read` 等带表名前缀的字段名，冻结评分将其列为非目标字段。统一去前缀的**事后格式诊断**为45正确、9未知、12遗漏，双位置仍9；原主分数保留。这不能当生产源码理解错误或幻觉。CodeWiki有一次TLS失败，4个绑定仍在分母，失败与信息未知分开；不能以此宣布完整CodeWiki不如候选。

主实验的 `production_reader` 保留实际文件取样及 read_file 行为，但用适配的读取选择/描述格式，另有默认源码用于选择阶段，并非精确输入信息匹配或完整生产报告。官方CodeWiki只原样运行C组件抽取，不是完整层级文档/工具系统。它们的分数不能当这些系统的端到端效果。

为补充核查，另按 [独立补充协议](production-probe-protocol.json)实际运行原生产SUBSYS系统模板及请求：OpenCode项目配置缺失、MCP Python包缺失，所以用私有API适配器执行原有工具函数；没有改提示。3次请求后因下一次请求的保守token预留触及60k子预算而停止，仅有6次工具结果，**没有完成子系统报告**。未把这次不完整运行作为候选优势，也未继续扩大预算。

## 预算和成本

主实验30个方法格，32次真实请求、31个有用量的回复，成功回复报告109,962 token；一次TLS失败未返回用量，不计为零费用。补充生产运行3次请求、26,208 token。合计35次请求、已报告136,170 token；失败请求另保守预留20,000 token，仍在默认60次/200k阶段上限内。主协议上限42次/180k，实际未超过；补充协议在首次补充调用前另行记录，没有放宽候选胜出门槛。

各方法独立运行主实验成本：生产适配12次/43,886 token，BM25 6次/25,893，官方组件适配6次/19,260已报告token+一次用量未知，候选6次/14,302，简单查表6次/14,403。共享调用不重复计入真实账本；微小token差不构成质量增益。

请求和返回模型均为 `deepseek-flash`，非思考，温度0.2；模型别名不能固定服务权重。官方价格已核查；按所报告cache hit/miss和输出token、峰值单价估算约USD 0.0423，**不是实际账单**。余额接口两次均显示人民币1.55，不能据此认定免费或精确费用为零。投影复核CPU单独测量在 engineering-observations.json；初次准备/编译CPU未单独计时，保持未知，没有编译或启动OS。
