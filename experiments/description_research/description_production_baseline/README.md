# 当前生产 SUBSYS 有预算探测：尚无完整报告

ChibiOS 便携 RT 核心的公开切片，使用当前原 SUBSYS system/user 提示和实际 quick_subtree/read_file/search_code 函数，直连 API + 四工具适配器。不是完整 OpenCode/MCP、VERDICT、语言护栏或最终四报告执行。源代码 slice 与确认材料的使用记录见相邻目录，不能称为盲测。

7 个唯一付费请求、150,853 个实际 token、12 次成功分析查询，第 13 次触及本探测的分析预算。没有写出完整报告，描述语义质量保持**未知**。仅写接口“通过校验”也不会是效果证据。当前原生产服务器默认分析上限是 20，写报告绕过分析计数；本适配器按 SUBSYS 的 12 次建议施加了更紧上限。因此这个停止结果不是原生产系统在正常全部预算下必然失败的证据。

复现必要的原请求、回复、工具消息可通过 run.py 的原函数重新产生；阅读应先看 outputs/audit.json、protocol.json 和 receipts。已有回复不得反复重新付费生成来救成功。

实施过程的异常均保留：

- 初次 AST namespace 缺少 __package__/__name__，相对导入失败。修正后复用完全相同的原第一条回复，无额外第一条模型请求。
- 全 UTF-8 JSON 字节作为每步输入 token 预留过于保守，58,960 已报告 token 时停止；换为已有前缀实际 prompt token + 新追加消息字节上界/格式预留，原 120,000 ceiling 未改变。
- 84,896 已报告 token 时再次预留停止；在新请求前明确公告并冻结基线子预算 120,000→184,000，父阶段仍 200,000。修正写报告工具不占分析步数。前五个原回复完全复用，没有提示改写、接口重试或重复收费。
- 最终第 7 条回复要求进一步读取，触及本适配器 12 次分析限制；保留停止结果，不再增加预算以完成这个观测。

第二阶段合计：名称污染控制 8 请求/12,356 token + 本探测 7 请求/150,853 token = **15 请求/163,209 token**；均有用量，没有新增未知收费调用。此前第一阶段另有 35 请求/136,170 已报告 token 和 1 次 TLS 未知用量，不在这里隐去或合并成零费用。

总体仍没有适合宣称的新论文方法；研究目标继续。下一条机制实验必须在新请求前冻结其协议和预算，不能把这个受限适配器当唯一生产强基线去制造正结果。
