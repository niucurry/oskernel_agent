# 描述可定位性中的名称污染：有限诊断成立，独立方法未成立

原型用维护者的 22 条服务 Purpose 文本作查询，参考答案来自官方手册身份与源码定义交集。题意不是模型编的，读者回复按固定源码身份复算。此机制只衡量“功能说明能对应哪个来源”，不验证任意自然句正确、不证明内核能力或真人评委效果。

两次重复均观察到：

|控制|正确源码身份/22|
|---|---:|
|正确说明，遮蔽 API 名称|21|
|职责错配，但露出 API 名称|18|
|相同错配说明，遮蔽名称|0|
|只列 API 名称，没有职责正文|22|

即使提示明令不要凭名称先验覆盖文档，错误说明仍获 18/22；名字清单获满分。遮蔽有效去掉这组污染，原固定敏感性门槛通过。

但是，按职责文本做精确词重叠的简单方法对原文控制就能得到正确说明 22/22、错配 0/22、无职责 UNKNOWN 22/22。因此**不把这组试验宣布为超强基线的新论文方法**。正确/错配控制使用相同原 Purpose 文本，检索难度很低，没有独立中文转述/真实生成报告验证，也没有留出项目确认。后续可复用污染控制来验证新的生成机制，不能把该诊断升级为整份描述正确率。

实际 8 请求、12,356 token，所有回复均有用量，无接口/格式失败，无自动重试。与职责预算候选共享阶段 2 的 60 请求/200,000 token；剩余 52 请求、187,644 已报告 token 额度。前一阶段另有 35 请求、136,170 已报告 token 和一次未知 TLS 用量，不隐去累计费用。

- `python3 recompute.py`：无密钥、无网络重算结果和冻结哈希。
- `probe.py`：会实际调用私有配置中的 API；已有结果不应重复付费重跑来寻找正分。
- `protocol.json`：事前预算/门槛/简单基线/局限。
- `calls/`：完整请求和回复，保存公开材料及读取任务，不保存鉴权头/密钥。

QAEval 问答评测与名称遮蔽已有研究，见相邻 candidates.md。此阶段未执行其大型预训练实现，也未冒充官方复现或人工研究。
