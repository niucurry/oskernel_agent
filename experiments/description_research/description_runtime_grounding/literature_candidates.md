# 真实运行之后的候选筛选

这是新的检索和淘汰记录，不是事前实验协议，也不宣布方法成功。第三阶段只运行既有生产基线，没有运行下面论文的完整系统。停止主线及先前候选的停止结论保持。

| 实质不同的候选问题 | 对应真实描述缺口与评委用途 | 最近方法、独立参考与适用强基线 | 本次决定 |
|---|---|---|---|
| 用文档消费者的执行结果优化功能解释 | 有引用和中文正文仍不能确定其可用于理解接口；评委需知道实现机制是否表达清楚 | DocSearch 已定义文档优化为重建代码的测试通过率，依赖顺序、beam 搜索和不回退条件均已有；独立测试可验证有限功能，不能当评委理解效果。其公开 Python/Java 实现不能直接当本轮 C 内核全系统强基线 | 单纯把重建与测试反馈移植至 OS 不足以证明机制差异；不开展新的测试生成、调用图或旧局部修复路线 |
| 让描述含可机械核对的表示事实 | 原路径验证仅证明文件存在，不证明自然语言中的数据表示或结构关系；评委需要分清确切表示与推断职责 | 受控自然语言文档验证早已把代码事实与逻辑理由结合；编译器可作固定目标下的窄参考，但简单编译事实模板对其所能评分的数值/结构事实已很强。还缺本次生产中可独立核对的表示错误例子，不能先选方法再造瓶颈 | 暂不选择。“编译器事实 + 生成器 + 标签”仍是普通拼装；不把未测量的全文错误率当需求证明 |
| 根据评委的信息任务调整解释重点 | 当前统一模块模板既写总体职责又写细节，未知哪些陈述实际帮助评审定位或理解 | Dhakal 等 refocusing 已基于程序员理由提出七个质量轴，并做定向模型对齐；DOME 的意图引导也已有。已有独立开发者数据不自动变成中文 OS 评委真值，简单轴提示必须作为强基线 | 增加“评委视角”提示、角色或调用者上下文不足以立为新方法；本次不训练大模型，不用助手代做开发者标注 |
| 以真实架构问题验证整份模块报告 | API 名称可使报告读者绕过正文；需要区分定位、事实与解释效用 | RepoProbe 发布真实 GitHub Discussions 架构问题与事实清单，但公开评分仍调用模型。已有名称控制只作诊断，不能把仓库/语言替换包装成新评测方法 | 可借其问题类别理解任务，不把模型清单评分当独立真值；不重新立项已停止的名称控制候选 |

原件与官方实现：

- [DocSearch 作者原论文](https://people.cs.vt.edu/penggao/papers/escaping-icml26.pdf)、[作者实现](https://github.com/ccsnow127/docsearch)。已读问题定义、搜索、不回退条件、基线、生成测试/独立测试区别与人工研究。论文另有 30 个发生实质变化的实体、6 个模块、5 位标注者的配对质量评分，不能说它完全没有人工验证；该结果仍非本轮 OS 评委任务实验。公开仓库明确仅发布部分代表性运行，不能推断全部任务成功率。
- [受控自然语言核验原文](https://arxiv.org/html/1311.2702)、[AceWiki 官方项目](https://github.com/AceWiki/AceWiki)。原文代码模型/核验和实现章节已读：Pharo/FAMIX 代码事实、ACE/OWL/FaCT++ 推理及多人实验。该方案不是任意中文自然语言的完备语义验证器，也不能把一致性直接当运行事实。
- [refocusing 原论文](https://onlinelibrary.wiley.com/doi/10.1002/smr.70157)、[作者实现](https://github.com/apcl-research/improving_summary)。原文介绍、方法和评价经网页工具读取；直接原件下载返回 403，失败保存。README 确认 GPU/Torch 模型流程，没有运行它或声称已核对所有公开人类原始标注。
- [RepoProbe 作者仓库](https://github.com/Qinyun718/repoprobe)，论文 DOI `10.1145/3832783.3837452`。README 说明加权清单由模型评分；DOI 链接读取失败，不冒称完整读过论文。随后按原 revision `d9b0859d2b6f3bd790017bf771c1f1c6546b1aaa` 核实 scorer.py / prompt_templates_en.py：调用评分 API，默认 gpt-5.2；模板要求模型自行核对，hallucination 标志仅约束虚构路径。事实清单不是已执行的独立语义核验器。未运行付费评分或完整 benchmark。
- [CodeClarity 官方介绍](https://huggingface.co/CodeClarity)、[ACL 作者页面](https://aclanthology.org/people/drishti-sharma/)另提醒多语评价已含标识符/文字脚本检查与模型评分；本次只读介绍，不声称运行 benchmark 或其指标能作中文 OS 真值。

本次排除了上述直接移植或提示拼装，没有把“检索发现已有工作”写成新的机制正结果。仍需要机制不同且可以公平核验的生成方法；第三阶段失败链与工程修复提供了交付瓶颈证据，而不提供这些候选的语义收益。

原件下载和初次 GitHub 大请求的 403、IncompleteRead、超时均保留在 recent-primary-retrieval.json；之后改用小 Git ref 和固定 revision 的单文件 API，8 个文件核对 Git blob / SHA-256 成功，另有不存在路径及 TLS 超时记录，见 recent-official-files-retrieval.json。没有通过安装完整训练/测试框架消耗磁盘，也未把成功下载说成成功复现。DocSearch 固定源码为 `48d3c4a2d0bd17b843f8751c2936f7a3ffd744db`。
