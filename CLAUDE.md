# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

An AI-powered agent that automatically evaluates submitted OS kernel code (C or Rust) for **completeness** (which subsystems are implemented) and **originality** (plagiarism detection against reference implementations).

The agent runtime is built on **OpenCode** (an OpenAI-compatible LLM agent CLI). This project supplies:
1. an **MCP stdio server** (`mcp_server.py`) that exposes OS-kernel-specific analysis tools, and
2. a thin Python **launcher** (`agent.py`) that resolves the target repo, generates the system prompt, and spawns `opencode run` with the right arguments.

## Setup & Commands

```bash
# One-click environment setup (installs opencode-ai, ctags, clangd, bear, rust-analyzer, Python venv)
bash setup.sh
source .venv/bin/activate

# One-time global registration of the agent + MCP server in ~/.config/opencode/opencode.json
python setup_opencode.py

# Fetch and analyze in one step
python agent.py --url https://gitlab.example.com/repo.git

# Analyze a repo already in data/historical_repos/
python agent.py --repo-id REPO_NAME

# Analyze a local repo by path
python agent.py --repo-path /path/to/repo

# Analyze using default repo_id from config.toml (if set)
python agent.py

# Save report to file (default goes to data/reports/<repo>_<timestamp>.html)
python agent.py --repo-id REPO_NAME --output report.html

# Direct OpenCode invocation (after setup_opencode.py has been run)
opencode run --agent os-kernel-analyzer "分析 /path/to/repo"

# Only clone (no analysis)
python fetch_single_repo.py https://gitlab.example.com/repo.git

# Build reference fingerprint database for plagiarism detection (optional)
python scripts/build_reference_db.py --reference rcore-tutorial-v3 --repo-path /path/to/repo
```

**No test suite exists** — validation is done by inspecting generated assessment reports.

## Configuration

The project is locked to the **DeepSeek** model (`deepseek/deepseek-chat`). In `config.toml` (git-ignored) you only need to set the API key and `base_url`; no `--model` flag exists. CLI flags `--repo-id` / `--repo-path` / `--url` / `--output` choose the target and report path without editing the file. After changing `config.toml`, re-run `python setup_opencode.py` to push the changes into `~/.config/opencode/opencode.json`.

```toml
[api]
key      = "sk-..."                          # DeepSeek API Key
base_url = "https://api.deepseek.com/v1"     # Switch to a proxy URL here if needed

[data]
repos_dir    = "./data/historical_repos"
metadata_dir = "./data/metadata"

[target]
repo_id = ""   # Optional default; leave empty to require --repo-id / --url / --repo-path

[engine]
rust_analyzer_timeout = 120   # Path A index wait (s)
clangd_timeout        = 60    # Path B index wait (s)
max_call_depth        = 3     # get_subsystem_call_chain default depth
max_steps             = 200   # MCP per-session tool-call budget
skip_dirs = ["vendor", "third_party", "target"]
```

## Architecture

### Entry Points
- **`agent.py`** — Launcher: parses CLI, resolves repo path (cloning when `--url` is given), builds the user request, then `subprocess`-invokes `opencode run --agent os-kernel-analyzer`. Also contains `select_engine()` and `_build_structure()` helpers shared with the MCP server.
- **`setup_opencode.py`** — One-shot installer that writes the `os-kernel-analyzer` agent definition and the `os-kernel-tools` MCP server entry into `~/.config/opencode/opencode.json`. Re-run safely to refresh the system prompt or paths.
- **`mcp_server.py`** — MCP stdio server launched as a child of OpenCode; owns per-session analysis state and exposes the tool set below. Supports a `--max-steps` budget and multi-context state for compare mode (`""`, `"a"`, `"b"` keys).
- **`fetch_single_repo.py`** — Clones a repo into `data/historical_repos/` and writes metadata; also callable as `fetch_repo(url, ...)` from `agent.py`.
- **`prompts.py`** — Builds the layered system prompt (Layer 1 role → Layer 2 deterministic facts → Layer 3 workflow rules) injected into the OpenCode agent at launch.

### Analysis Engines (`engines/`)
Three engines with automatic fallback selection in `agent.select_engine()`:
- **Path A** (`path_a.py`): `rust-analyzer` via LSP — used for Rust repos (have `Cargo.toml`).
- **Path B** (`path_b.py`): `clangd` via LSP — used for C repos (needs `compile_commands.json`, generated by `bear`).
- **Path C** (`path_c.py`): `tree-sitter` AST — fallback when no LSP is available.

`base.py` defines the abstract `AnalysisEngine` interface (`go_to_definition`, `find_references`, `get_call_chain`, `get_struct_fields`). `lsp_base.py` provides a shared `LspEngine` base used by Paths A and B.

### Static Analysis (`parser/`)
- **`code_parser.py`** — Detects source roots, primary language, naming style, kernel type, target arch, build env, doc files, and structural anomalies. Runs `universal-ctags` and classifies symbols into Level 1 (prominent, injected into prompt) and Level 2 (queried on-demand). Also builds call graphs via tree-sitter.
- **`os_tools.py`** — `Level2Index` (symbol lookups by name / file / subsystem) and `build_repo_map()` for the structural map.

### MCP Tool Layer (`tools/` + `mcp_server.py`)
Tools exposed to the OpenCode agent during its reasoning loop:
- `initialize_analysis` — Run static analysis on a repo and return the Level 1 code map (must be called first per session).
- `read_file` — Read source files with optional line range.
- `search_code` — Keyword / regex search across the repo.
- `find_symbol_definition` — Locate a symbol's definition (uses engine).
- `find_symbol_references` — Find all call sites of a symbol.
- `list_implemented_syscalls` — Scan for syscall implementations.
- `get_subsystem_call_chain` — Expand call trees from an entry function (depth via `max_call_depth`).
- `compare_with_reference_os` — Similarity check against a reference fingerprint DB.
- `write_report` — Persist the final Markdown assessment to `--output-file`.

`tools/mcp_tools.OSKernelMCPTools` is the unified entry point (subclass of `ToolDispatcher`); `tool_dispatcher.py` aggregates engine + index + repo context; `tool_handlers.py` has the low-level implementations; `reference_db.py` manages the fingerprint database used by `compare_with_reference_os`.

### Agent Loop (driven by OpenCode)
```
agent.py: parse CLI → resolve repo (fetch if --url) → build user message
     |
opencode run --agent os-kernel-analyzer  (subprocess)
     |
OpenCode: LLM loop with system prompt from prompts.py
     |
Tool calls dispatched over MCP stdio to mcp_server.py
     |
mcp_server.py: initialize_analysis on first call → engine selected (A→B→C)
     |
Per-session safeguards: hallucination tracking, duplicate-call rejection,
                        max_steps budget, suffix-variant blocking
     |
write_report → final Markdown assessment (stdout or --output file)
```

**Hallucination protection** lives in `mcp_server.py`: failed symbol lookups are tracked per session; suffix-variant re-queries are rejected; on repeated hallucinations the server injects a termination directive (`[保护] 注入终止指令` appears in output).

## Data Layout

```
reference_db/                     # Code fingerprint JSON files (one per reference OS)
data/
├── historical_repos/<repo_id>/   # Cloned student repos (git-ignored)
├── metadata/all_repos_info.json  # Commit history metadata
├── reports/                      # Generated assessment reports
└── os_knowledge_graph.db         # Optional persistent symbol graph
```

## Key Dependencies

| Package | Purpose |
|---|---|
| `opencode-ai` (npm, global) | LLM agent runtime; spawned as subprocess by `agent.py` |
| `mcp[cli]` | MCP stdio protocol used by `mcp_server.py` |
| `openai` | API client (OpenAI-compatible, used for DeepSeek/Claude) |
| `tree-sitter` + `tree-sitter-c` / `tree-sitter-rust` | AST parsing for Path C engine |
| `gitpython` | Repo cloning and metadata extraction |
| System: `universal-ctags` | Symbol extraction |
| System: `clangd`, `bear` | C LSP and compile-DB generation |
| System: `rust-analyzer` | Rust LSP |
