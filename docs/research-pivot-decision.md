## 已有方法的结论

**停止将“构造/拼接行为图，展示给模型以增强代码理解”作为论文核心。** 图在限定环境下能记录真实执行，但没在强对照下稳定提高模型回答或摘要质量。

| 检验 | 直接结果 | 判定 |
|---|---|---|
| 新功能问答 | 源码 63.54%，源码加图查询 62.15% | 没有理解增益 |
| 条件行为单元问答 | 源码和源码加单元各 90/100 字段；链表退步 | 整体持平 |
| 真实跨调用状态卡 | 两次各 30/40、33/40；仅源码和示例 31/40、34/40；提示 token 5,741 对 1,338 | 更贵，未改善 |
| 冻结迁移 | xv6 和 Nginx 两个新功能均未过预定门槛；简单输入树更优 | 不具迁移优势 |
| 源码一致性 | 有限 Nginx 输入 180/180 与原始 C 七字段一致 | 证明该夹具内实现可信，不证明智能体更懂代码 |

明细：迁移实验、条件单元、跨调用状态卡分别保存在[旧归档](retired-experiments-2026-09-27.md)内的 `docs/independent-transfer-development.md`、`docs/conditional-behavior-units-development.md`、`docs/cross-call-state-transfer-development.md`；[证据审查](novelty-and-evidence-audit.md)仍保留在工作区。这些实验不足以证明行为图对所有任务都无效，但已经足以停止**本项目当时对该方法的研究投资**。不再继续调分组形式、提示词或同一批开发函数来追求正数。

## 新主线

目标改为：**让仓库级功能审查报告的每条实质断言可检查，同时找出重要但未写到的行为和证据空白。** 研究对象是报告质量与审查决策，而不是“模型看了图是否感觉更懂”。系统分四步：

1. 智能体从仓库源码生成一份功能报告，并拆成原子断言，如“失败时释放两个句柄”。同时记录它查看的文件/函数和未查看的范围。
2. 独立核验器对每个断言选择最廉价的可用证据：现有测试、编译执行的小夹具、源码定位/静态查询。若现有行为图有帮助，也只能作为其中一个工具。核验器输出支持、反例或无法核验，以及适用前提。
3. 用入口、公开接口、错误路径及人工预列的关键行为清单审查**遗漏**。只删错误断言却丢掉大量真实功能，不算成功。
4. 报告显示已核验结论、反例、未知边界和覆盖范围。原始自由文字不能因“引用了工具包”就自动标成已验证。

这仍是**待检验的研究假设**。功能级仓库摘要和代码追踪已有 [RepoSummary](https://arxiv.org/abs/2510.11039)；密集、经专家核对的仓库代码审查数据已有 [AACR-Bench](https://arxiv.org/abs/2601.19494)；从自然语言规则抽取并检查代码已有[工业案例研究](https://arxiv.org/abs/2605.17926)。因此“生成断言再核验”本身不是新发明。若论文要有贡献，必须在遗漏检测、无法核验边界和成本受限的实证上证明明确优势。

## 一次小型淘汰实验，不再无限迭代

先选此前**没有用于调算法**的两个仓库，各三个功能，覆盖正常和失败路径。冻结每个功能的关键行为与人工参考断言，包含现有工具无法检查的断言，不能事后从分母删除。让同一模型在相同时间/token 预算下产出报告；比较三种后处理：无后处理、模型自查、直接源码搜索与测试。候选系统只能在相同预算内使用额外工具。对同一批原子断言比较错误接受数、正确保留数、遗漏数、人工复核时间和总成本；按仓库分别报告，不能只报合并平均数。

**继续条件：**在两个仓库上，候选方法都须在相近的正确断言保留量下减少错误接受，并且遗漏不增加；若直接测试/源码工具达到同样或更好的效果，就不把行为图写成方法贡献。若新方向也没有净收益，停止继续造摘要架构，转向发布复现实验、失败分析和受限行为证据工具，重新评估论文题目。正式论文实验必须另外冻结更多仓库和专家标注；这次小实验只用于决定研发投入。

现有图执行器和状态卡保留为工具库，既不删除，也不再作为摘要智能体的默认上下文。原比赛报告系统维持运行；研究原型与正式报告是否集成，取决于新方向通过上述门槛。
