# 开发历史证据的冻结实验与独立工程修正

本阶段从生产开发过程报告的真实统计口径出发，保留旧研究负结果，不恢复行为图、条件 JSON、条件压缩或其变体。当前结果支持保留系统修正，尚不支持一条合适的论文方法。实验实现和原始材料见 [history_evidence_audit](../research/history_evidence_audit/README.md)。

## 研究判定

原始问题是：默认 Git numstat 会否漏掉合并解决时产生的源码变更，以及父关系证据是否提供普通 Git 基线以外的能力。事前冻结 seL4、Redox、Phoenix-RTOS 三个此前未检查的通用 OS 仓库，固定 depth=128、每仓库最多 16 个双父合并、每个残余最多两个按字典序选取的源码路径；禁止结果后加深历史、更换仓库或调阈值。它们不是经过认证的正式参赛提交，不能作为比赛总体样本。

主假设要求至少两个仓库出现完整的源码合并残余且旧生产统计为零。三个冻结头合计 465 个可见提交；只有 Redox 有两个可见合并，一个 remerge 残余为零，另一个缺少祖先。没有支持仓库，两个源码主假设均未获支持，且实际上没有符合条件的源码 blob 比对。第一个合并对第一父提交的 4,150 LOC 整合差分不能当成新解决逻辑或个人工作量。普通 Git 父差分、remerge 和保守源码身份比对已覆盖原型能力，因此停止新算法主张。

这是有范围的负结果；合并数量稀疏、浅历史缺失限制外推，不能宣称所有合并研究彻底不可行。101 对作者日期不递增的相邻提交只是元数据观察，不能推断伪造、开发效率或违规。[时间数据研究](https://arxiv.org/html/2209.04511)已有相应研究背景；[合并冲突原始实证研究](https://ics.uci.edu/~iftekha/pdf/J4.pdf)及其公开实现亦需作为既有工作，而非被包装成项目的新颖机制。

## 可保留的系统收益

结果后直接观察到四个浅克隆边界被默认差分当成空树导入，统计为 4,419、41,713、94,540、237,532 LOC，均进入大规模提交候选；原始对象仍声明父提交，所以这些数不能代表原始提交的真实差分。真实原始差分缺失，保持未知。随后单独冻结五类工程控制，明确不将其算作研究主假设成功。

本地完整上游真值的控制中，边界只替换一行，真实差分为 2 LOC，旧浅统计为 1,202 LOC。修正后原始 numstat 仍保存，但不能参与大规模提交判定；后续普通提交的 2 LOC 保留。真正首次导入和被 shallow 标记的真正无父根提交仍保留已知的大规模正例。双父合并在未测量父差分时报告未知，不能写作零。作者时间、提交者时间和父关系分别保存，报告阶段采用作者声明日期的 UTC 范围，不把遍历首尾当实际工作起止。

同一三个 OS 头的修正后检查保留全部 465 个提交身份和顺序，四个浅边界退出无依据的大规模候选，两个 Redox 合并保持未知。HTML 与摘要 digest 的未知量标注均已检查；这里只改证据统计及交付事实，没有运行模型或修补旧提示方法。

相关报告回归 204 项通过。首次运行的两个 PDF 测试因未指定已有中文字体失败，保留完整日志；配置已有私有字体后通过，未修改 PDF 实现。工程控制与回归通过只证明实现行为符合所定证据口径，不是论文准确率。

## 成本和下一步边界

三个 bare 克隆共 4,028,038 字节，获取 8.04476 秒墙钟 / 0.391904 秒子进程 CPU；主检查 23 条 Git 命令、0.265926 / 0.243124 秒；独立工程阶段含控制仓库创建、前后收集和真实 OS 后检查，98 条 Git 命令、0.594005 / 0.41491 秒。预备、测试和哈希时间另计；没有性能领先结论。模型、内核构建、启动次数均为零，先前 392 个实际运行单元总数未增加。

保留开发报告修正和所有失败材料，停止这个冻结合并候选的投入。总研究目标继续：下一项应提供新的、独立可核查的 OS 评审效果证据。既有算法与生产修复相等不排除实证论文，但必须先验证自然样本中的实际影响、强基线和数据适用范围；不能把本阶段的工程收益改写为主假设成功。
