# 重新选题与已执行先导：OS 评审成绩能证明什么能力

2026-10-03。完整交接已读。本轮未重启行为图/状态卡、条件 JSON、描述压缩的损失追踪或局部修复。没有恢复旧实验、改提示后重跑旧任务，也没有改生产源码或旧负结果。

**优先保留的新问题是：操作系统评审测例的通过判定，是否对它所声称测量的系统操作敏感？** 目前有实际执行证据支持这个问题值得继续；尚未得到胜过强基线的新算法。两个具体候选的新增方法贡献都被淘汰，保留工具和负结果。该结论不能写成“已找到可投 TSE/TOSEM 的方法”。

## 1. 从生产系统和真实评审需求出发

系统面向评委，产出功能描述、开发过程、同源对比和一页摘要，目的是减少人工复核范围。以下瓶颈来自现有代码，而非从旧摘要实验推导：

| 当前实现及位置 | 实际限制 | 评审需要区分的事实 |
|---|---|---|
| `analysis/repo_facts.py` 的 `_probe_standard_syscalls`、`_probe_syscall_dispatch`、`_probe_smp` | 正则定义、分发表和多核唤醒名称是线索；已有 `source_note` 正确提醒它们不等于可用性 | 接口出现、被当前构建纳入、实际调用、行为正确，是不同证据 |
| `finals/integrity.py` 的 `scan_hardcode_signals`；`pipeline/tree_builder.py` 的逐条复核 | 测试名、缓存、输出“通过”等模式只产生风险候选；模型审查没有独立运行效果参考 | 合法兼容处理、测试特化、真实语义旁路不能只靠字面特征区分 |
| `comparison/report/upstream_baselines.py:219`、`:453` | 同上游根下相对路径相同可将整个函数标成上游，未要求实际上游内容解释该函数 | 公共上游部分与队伍在已有文件中的修改不能整函数一并排除 |
| `pipeline/tree_builder.py` 的文件取样、模块槽位、工具窗口上限 | 已修复的目录/语言轮流取样仍是有限输入；引用存在不等于已覆盖所有重要实现 | 覆盖与未知必须独立记录，不能把未观察当未实现 |
| `finals/integrity.py:1007`、当前 `cli/agent.py` | 当前 `collect_integrity_facts` 只采硬编码，构建验证仍是独立库函数；README 的 `--verify-build` 等说明与当前入口不一致 | 未执行的编译/运行不能作为已获得的证据。本轮记录脱节，未将文档修补当研究成果 |

联网核对的 [2026 决赛官方资料](https://github.com/oscomp/testsuits-for-oskernel/blob/b5ec6ef8497e1818cbdec3b54bb722f036e57972/README.md)包含 CAgent 与 BuildStorm，也要求解释性能瓶颈、实现优化和可复现步骤。因此，项目的实际研究范围可以延伸到测例有效性、能力证据与原创修改，而不必继续优化摘要文本。公开自测 judge 与正式平台判定要分开。[官方运行环境](https://github.com/oscomp/autotest-for-oskernel/blob/d1bb3a3c4b27274e196a2648518525c1a304e339/README.md)还要求比赛镜像与两种架构的磁盘/仿真环境。

工作区没有真实参赛队的可用克隆/运行产物；`data/` 现有材料主要是保留的旧摘要。当前没有 Docker、QEMU 或交叉 GCC 命令。宿主 GCC 12 可用，模型外部配置可用。没有将这些缺口说成整个研究不可行；本轮先取得可以独立核对的有限证据。

## 2. 跨方向比较和选择依据

以下四项的核心问题实质不同。预算列除已执行项外均为先导上限估计，不是实测费用。选择依据是评审关联、已有失败依据、独立参考可获得性及强基线；没有凭论文标题宣称学术空白。

| 方向 | 具体问题与已有依据 | 可能新增的机制及可推翻的解释 | 强基线、参考与覆盖评价 | 实施性、预算与判断 |
|---|---|---|---|---|
| A. 构建配置下的功能审查覆盖 | 源码中出现的功能可能没有纳入提交产物，当前事实采集扫描整个源码树 | 将评审功能/修改映射到实际构建输入与产物，按评审重要性选择少量构建。若编译数据库、预处理输出和 Cargo dep-info 已同样覆盖，则新增机制不成立 | 编译数据库、编译器依赖输出、链接 map；参考来自编译工具真实记录。必须报告未编译、内联/消除、无法映射部分，不能把构建纳入当运行正确 | 工程价值高，配置分析已有成熟方法，创新风险高。估计先导 3 仓库、12 次构建、0 模型调用、最多 2 CPU 小时；工具链准备成本较高。本轮只调查，未执行 |
| B. 测试特化行为的语义干预 | 硬编码扫描命中后仍靠模型判断；合法路径兼容与语义旁路混杂 | 对规格允许的测试身份/名称/资源变换进行一致干预，观察行为是否违反应保持的关系。若普通 POSIX 测试同样发现、或变换改变合法语义，则否定机制 | 原扫描＋复核、普通测试、等预算随机/边界测试；POSIX 规格、Linux 对照及真实运行。把无法证明变换适用的项留为未知，不认定作弊 | 与评审直接相关，潜在研究空间较大；最难的是变换合法性和整 OS 运行。估计先导 2 内核、每个 6 组干预、24 次启动、0–20 模型调用；缺少当前运行环境，未执行 |
| C. 同源证据中的上游与本地修改分离 | 路径规则可以解释上游目录，却不能证明其中每条修改来自上游 | 仅扣除被上游解释的片段，比较两作品共同残余。若规范化已知上游 diff 得到相同结果，则不构成新增方法 | 实际生产路径策略、规范化已知上游 diff；正式还需 CENTRIS/TIVER 与 Dolos/JPlag。受控插入的来源是有限真值，未知版本要计入分母；共享残余不等于抄袭 | 已实现 6 函数、2 项目、36 个受控案例，0 模型调用。路径风险得到复现；候选与强 diff 基线完全相同，淘汰新增算法主张 |
| D. 测例的能力归因与负控制敏感性 | 官方 CAgent 多项只检查输出数字/关键词，部分文件检查没有要求本轮新产生状态 | 对返回文本、旧状态、失败退出和真实 syscall 阻断做分层干预，检验成绩是否区分能力有无。若阻断使所有对应判定拒绝，则否定脱节解释 | 官方完整脚本、仅看进程退出、精确值/终态、任意命令记录、相关操作记录＋结果；参考是控制构造、子进程执行和文件快照。完整十项入账，分别记录失败与未知 | 本轮优先选择：官方需求直接，宿主参考可自动取得，成本低。已完成 140 个控制、完整脚本 3 次、20 模型调用、32 个 syscall 工作进程、6 个 BuildStorm judge 输入 |

A 研究编译纳入，B 研究被审代码的测试特化，C 研究来源解释，D 研究判定对实际能力的敏感性。四项都不依赖旧描述文本、压缩预算、模型读者评分或旧行为图后端。

## 4. 优先方向的预先协议

[主协议](../research/assessment_sensitivity/protocol.json)在第一次模型调用前写入源码版本、数据分区、两个 Python 程序的哈希、预算和停止条件。它是本地冻结，未经第三方时间戳注册。

- H1：十项官方 CAgent 中至少五项能被“没有执行任务操作、只返回文本”的控制通过；少于五项则推翻这项主张。
- H2：精确结果/终态检查本身足以证明请求中的操作发生；只要正确输出回放或旧状态通过而操作没发生，就推翻。
- H3：在这个可信宿主驱动中，相关操作证据＋结果能区分真实正控制与文本回放、无关命令、旧状态、错误输出、失败退出。任何错误接受或真实正控制拒绝均不通过。
- 新增候选再要求本轮状态变化。若与“相关操作记录＋结果”基线完全相同，停止将它当新增算法；不得把工程门禁正确率当论文增益。

十项全部是开发阶段完整清点，不是十个独立 OS。两次重复只检查稳定性。BuildStorm 是同一官方仓库的另一个诊断，不是盲测仓库。追加 native 阶段在响应控制结果之后单独冻结、随后编译运行，因此明确是机制迁移诊断。

模型预算：DeepSeek Flash、20 次、每次输出最多 512 tokens，总报告 token 上限 30,000，服务商可见余额下降上限 0.50 元；不重试、不换模型、不调提示。API 的 models/balance 查询成功，当前配置模型和 Pro 均列为可用。所有请求读取仓库外私有配置，未保存 key。模型仅是受测输出来源，任何判定真值都不由模型打分。

## 5. 实际结果与解释

### 5.1 单项控制与完整脚本

[140 条原始控制](../research/assessment_sensitivity/controls.json)、[分析](../research/assessment_sensitivity/analysis.json)及[完整官方脚本结果](../research/assessment_sensitivity/full-script.json)均保留。以下每格 20 次 = 十项 × 两次，不是 20 个独立程序：

| 判定 | 真实正控制 | 仅返回正确文本 | 无关命令＋文本 | 含错误/混杂结果的文本 | 预置旧状态 | 操作后失败退出 | 空输出 |
|---|---:|---:|---:|---:|---:|---:|---:|
| 官方谓词 | 20 | 16 | 16 | 16 | 20 | 0 | 0 |
| 仅进程退出为 0 | 20 | 20 | 20 | 20 | 20 | 0 | 20 |
| 精确值或终态 | 20 | 14 | 14 | 0 | 20 | 0 | 0 |
| 任意命令记录＋结果 | 20 | 0 | 14 | 0 | 0 | 0 | 0 |
| 相关操作记录＋结果 | 20 | 0 | 0 | 0 | 0 | 0 | 0 |
| 候选再检查状态变化 | 20 | 0 | 0 | 0 | 0 | 0 | 0 |

原样运行完整 shell 脚本与 judge 的三组结果：满足谓词的构造正控制 10/10；仅返回文本 8/10；预置旧文件、随后仅返回文本 10/10。完整脚本组使用 mock agent/server，并非真实 CAgent。所谓“没有任务操作”不包括 Python 启动、评测 shell、读取库及评测器自身动作；不能写成“完全不需要 OS”。

精确输出回放包含从正控制获取的答案，是定向负控制，不是一个自动能知道答案的攻击模型。混杂错误文本是构造控制，也不能将 16/20 解释为自然错误率。完整覆盖十项，运行失败和未知均为 0。主控制驱动记录时间约 0.872 秒，不含模型、准备和完整脚本。

H1 在限定范围内得到支持；H2 被推翻。H3 通过最初有限控制，但相关操作标签来自可信固定驱动，不是自动理解任意 shell 的工具。候选 140/140 与强 trace 基线一致，**淘汰新增算法主张**。

收尾另执行了[幂等操作诊断](../research/assessment_sensitivity/idempotence-results.json)，计划在该诊断运行前单独写入，但选择发生在主实验之后，明确是事后诊断，不并入原 140 个分母。三个文件操作各两次，在已满足目标的状态上真正再次执行。官方谓词与 trace 基线 6/6 接受，强制内容/目录项终态变化的候选错误拒绝 6/6。它进一步表明候选会损失合法操作覆盖；没有据此修改规则或重新挽救算法。文件时间戳等未纳入该候选快照，不能事后换状态定义抹掉负结果。

### 5.2 普通模型回复也会被接受

[20 次真实请求/响应和账本](../research/assessment_sensitivity/model-run/ledger.json)全部完成，无重试、API/解析失败或输出超限。直接给原始十项提示，每项两次，没有提供任何本地操作工具，官方谓词仍接受 11/20 个回复。

一个真实例子是模型明确表示不能访问系统，然后提供 `uname -r` 用法与示例版本 `6.8.0-45-generic`。官方版本谓词仍通过。网络和文件搜索的使用说明中包含数字或命令参数，也足以触发相应谓词。模型并未都声称完成任务，因此这个结果不能写成“11 次模型说谎”，更不能写成真实 CAgent 准确率。

服务商报告总计 **3,000 tokens**：prompt 446、completion 2,554；请求等待时间合计约 27.613 秒。余额查询前后都为 1.69 元，显示的余额差为 0.00；余额精度不足以给出真实人民币账单，不能据此宣称免费。剩余 27,000 token 预算没有为追正数而继续消耗。

### 5.3 真实 syscall 阻断诊断

[native 协议](../research/assessment_sensitivity/native/protocol.json)、[C 源码](../research/assessment_sensitivity/native/probe.c)、[编译记录](../research/assessment_sensitivity/native/build.json)、[32 次结果](../research/assessment_sensitivity/native/results.json)保留。

在工作进程内由 Linux seccomp 将指定 syscall 置为 ENOSYS，验证它确实返回 errno 38。评测进程在过滤器外。八个有限工作进程分别涉及 affinity、uname、openat、mkdir、getdents64、statfs；每个比较可用/阻断、重复两次，共 32 次。过滤器安装与操作参考全部有效，无失败；未阻断对照 16/16 被接受，阻断组 **8/16 仍被接受**，对应 cpu、network、fs-search、fs-usage 四项。原因是正常完成的外层进程打印 `ERROR … errno=38`，输出中的数字足以通过谓词。

这里明确区分进程正常结束与请求操作成功。不是在整个 OS 中移除功能，不是参赛内核，也不是正式 CAgent 的完整执行。`fs-usage` 工作进程查询的是 statvfs 文件系统容量，不等同于任意目录的完整 du 语义；CPU 是进程可见 affinity 数，network 只读取 IPv4 TCP。它们是受控 syscall/错误输出的诊断，不能用于给真实 OS 的功能完成率贴标签。该追加实验支持“错误诊断文本也能通过”的机制，不支持系统调用级全面正确性。

### 5.4 BuildStorm 的公开自测 judge

[六个原始输入与判定](../research/assessment_sensitivity/buildstorm.json)：空/明确失败日志为 0；仅构造成功文本为 180/180；`bytes=0` 但 `ok=true`、负耗时、`mode=single` 三种输入各为 160/180。没有实际执行 BuildStorm guest 构建脚本，它会改 guest 的 `/root` 和 `/work`。

只说明公开自测 judge 接受这些文本，不说明正式平台允许伪造成绩，不说明实际编译性能，也不能据此指控队伍。整个运行无 judge 进程失败。

## 6. 第二种机制实际执行后也被淘汰

[上游残余原型](../research/upstream_residual/probe.py)、[协议](../research/upstream_residual/protocol.json)、[数据](../research/upstream_residual/data.json)、[结果](../research/upstream_residual/results.json)。ArceOS 及 FreeRTOS-Kernel 各三个函数，官方 commit 与源文件哈希记录在协议中。原文件、共同插入、插入迁移、不同插入、仅格式/注释、缺失上游六种场景，总计 36 个案例。

这些是受控文本插入来源真值，不是实际抄袭数据，不验证功能语义，也不是盲测。FreeRTOS 的根通过实验私有 registry 加入，只检查相同策略，不改生产配置。旧实验涉及的项目没有被重新命名为全新留出。

生产路径策略会排除全部 18 个已知含共同非上游插入的案例。对 30 个有确切上游的案例，候选残余匹配没有误报/遗漏；其结果与规范化已知上游 diff **完全相同**。剩余 6 个无上游案例明确是 unknown，不能算清白或从分母去掉。追加去掉构造 pair 的预设相似度字段后，路径排除依旧触发，说明问题不依赖这些字段。

因此保留“现有路径扣除可能吞掉修改”的工程风险；淘汰 residual k-gram 作为新增方法。没有声称胜过完整 CENTRIS、TIVER、Dolos 或 JPlag，也没有把差分工具的普通能力包装成新研究。

## 7. 本轮决定与顶刊研究门槛

**继续的是 D 的实证问题，不是两个已淘汰的检查算法。** 最有依据的研究问题现在可写为：*在 OS 能力评估中，任务输出、代理工作流成功与内核能力成功何时脱节；有预算的能力干预如何识别这些脱节？* 这个目标直接改变评委可依赖的证据，比继续修饰功能描述更有依据。

当前有三个机制层次的观察：不执行任务仍通过；旧状态可以代替本轮效果；真实 syscall 失败诊断仍通过。它们支持继续研究测量有效性。通用状态检查、合同、执行追踪、变形测试和故障注入都有先例；单个公开测例套件的案例审查还不足以形成顶刊贡献。

正式确认的下一阶段需把算法与经验主张分开，门槛如下（**未运行**）：

1. 冻结至少三个从未用于调本轮机制的 OS 实现/版本及新的工作负载；不能把本轮 CAgent、BuildStorm、ArceOS 或 FreeRTOS 再称为盲测。采用可信宿主/仿真层施加能力干预，同时记录正常运行、环境不具备、编译失败、超时和非确定性。
2. 研究的基本单位是 OS × 能力 × 工作负载，不是数百次输出行。比较原判定、精确结果/终态、普通故障注入、执行/系统调用工具核验；只有新干预选择机制在同等可观测能力范围和时间预算下发现更多脱节，才能主张方法增益。
3. 首批上限：3 OS、每个最多 8 能力、每能力正常/干预各两次；最多 96 个有 timeout 的运行、8 CPU 小时、模型 0 次。下载/镜像与实现适配单独计时、计磁盘。每 OS 最多一次环境适配，不以反复修改程序或提示追求正数。
4. 若不能取得可信的能力移除证据、正常控制不稳定，停止效果统计并报告环境/测量失败；若只是检出构造错误、不优于普通故障注入/trace，停止新算法主张。若多 OS 表明脱节只限本次公开自测脚本，则保留工程工具，不把发现泛化到内核评审。
5. 若主张减少评委时间、提高真实评审准确性，则还需要独立评委研究；这不是开始自动机制试验的前置条件。本轮没有人类真值或用户研究结果。

本轮工具已能独立生成证据页、列出每项覆盖、未知、控制与原始依据，作为生产系统评审的旁路诊断。它还没有接入四份正式报告，也不能用于自动奖项、违规或抄袭结论。已有系统修复和历史负结果均保留；没有为新原型修改生产准入条件。
