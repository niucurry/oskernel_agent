# 行为图的创新性和有效性：当前证据审查

**当前主线已调整：**[研究方向决策](research-pivot-decision.md)明确停止以行为图展示增强模型理解为论文核心，改为验证仓库功能审查报告中的具体断言和遗漏。以下各轮记录保留原时间顺序，不能把其中较早的“下一步”当作现在的计划。

截至 2026-09-26，项目能把某个功能涉及的函数按具体调用位置拼成控制流图，保留返回位置、出口条件、未展开边界，并查询源码语句的顺序和有限对象状态。**这些实现目前还不足以证明顶刊级创新或模型理解能力提升。** 一项方法无法用实验“彻底证明”对所有代码都有效；合理目标是提出区别清楚的可证伪主张，在此前未见过的任务上反复测试。

**最新决策：停止将稀疏路径筛选作为当前研究主线。** [冻结迁移实验](independent-transfer-development.md)在 xv6 新功能和 Nginx 新仓库上均未通过门槛，普通输入树取得更好的错误率—覆盖率结果。Redis 的单功能正结果不能再作为通用价值的依据。已实现的[可核对摘要事实](checked-summary-development.md)能拦住真实错误，但反馈主要让模型删掉断言，没有产生新的实质功能知识；暂时只支持工程可靠性价值，不支持新的理解增强或论文创新结论。

**后续同日更新：** [条件行为单元实验](conditional-behavior-units-development.md)将同条件语句无损合组。2,400 字符内，管道源码要点覆盖由逐条展示的 7/12 提高到 11/12；强源码生成对照的最佳一次仍达 12/12。链表两种自动表示都达 10/10。20 个场景的模型问答中，两组字段正确数同为 90/100：管道改善，链表退步。因此可保留更紧凑的证据组织，但仍不能声称模型理解稳定增强；错误集中在跨调用状态变化及部分成功后的失败处理。下一项只围绕该具体缺口复用现有状态模块验证，不再把增加图展示等同于研究进展。

**跨调用实验已完成：** [状态卡与模型对照](cross-call-state-transfer-development.md)中，执行器在 180/180 个有限 Nginx 原始 C 输入上匹配七个最终字段，保留了重复调用之间的对象版本；但三个两次重复的模型对照均未通过理解增益门槛。真实压缩卡在 40 字段任务中两次得到 30、33，原始轨迹也是 30、33，简短源码加示例是 31、34；卡的提示 token 约为简短对照的 4.3 倍。故当前**停止被动展示行为图/状态卡来增强模型理解**的研究主线。保留可核对执行证据；下一项研究问题必须改为具体断言的主动反例核验，并与直接运行代码及普通测试作成本和错误率对照。以前提出的“跨调用状态是下一步”已执行，不应再当作待办。

## 哪些主张已经被先前工作覆盖

- “把语法、控制流和依赖放进代码图”已有 [Code Property Graph（IEEE S&P 2014）](https://www.ieee-security.org/TC/SP2014/papers/ModelingandDiscoveringVulnerabilitieswithCodePropertyGraphs.pdf)。其论文还展示了 Linux 内核上的图查询应用。因此图表示本身或内核规模不能单独充当新颖性。
- 跨过程依赖及程序切片早有 [Horwitz、Reps、Binkley 的工作](https://pages.cs.wisc.edu/~reps/)。[CodeQL 路径查询](https://codeql.github.com/docs/writing-codeql-queries/creating-path-queries/)也能展示跨函数的数据流证据链。因此“跨函数追踪”和“有路径证据”都不是首次提出。
- [RepoGraph（ICLR 2025）](https://proceedings.iclr.cc/paper_files/paper/2025/hash/4a4a3c197deac042461c677219efd36c-Abstract-Conference.html)已把仓库图接入软件工程智能体。[RepoSummary（2025 预印本）](https://arxiv.org/abs/2510.11039)已明确研究以功能为单位组织仓库摘要，并把功能关联到代码。功能级摘要和图增强智能体也不能笼统称为原创。
- “生成候选规则—校验—给反例—重试”是已有的 [CEGIS](https://digicoll.lib.berkeley.edu/record/134841?v=pdf) 范式；把短反例作为反馈不能单独声称为新算法。本项目若要构成新贡献，须证明**从跨函数行为图产生且可审计的功能反例/证据**在仓库摘要任务上的独特收益。

目前可能形成可发表贡献的是更窄的组合：**围绕功能入口，将调用位置、返回端口、出口限定的行为事件及未知边界组织成可查询证据；使摘要的每个顺序/状态结论都能追溯到源码与路径，并报告哪些函数和行为未被覆盖。** 这是一项待验证的研究假设，不是文献检索已经证实的新颖性结论。必须同已有程序分析工具、功能摘要方法做详细机制对比，再看实测收益。

## 现有证据分层

| 问题 | 当前证据 | 可得结论 |
|---|---|---|
| 拼接图是否保留原始 C 的执行路径？ | 既有多函数 C 差分与轨迹审计；新增 [出口限定事件顺序审计](event-order-development.md)覆盖 6,358 次正常运行，3,338 组被运行触及的必然顺序关系无违例 | 在所选函数和模拟输入范围内有正面证据；不等于所有路径和仓库都正确 |
| 对象身份及写入版本是否正确？ | [对象状态实验](object-state-development.md)的 1,152 次限定执行及 2,082 个 C 观察点一致，故意错误的图会被发现 | 对这两个功能的有限执行器有效；不等于任意 C 的别名/内存静态分析 |
| 模型是否更理解代码？ | [新任务对照](query-transfer-development.md)中源码 63.54%，源码加图查询 62.15%；[对象版本对照](object-version-comparison.md)中被动图展示没有稳定收益。固定三条短反例在 PostgreSQL 上使初稿平均从 33.33% 升至 50.40%；[行为图选反例与四案例关系对照](causal-counterexample-development.md)中，增加图选覆盖没有增益，直接补充图核验关系也没有提升 | 有很窄的“有限功能规则可由短反例帮助修改”的开发集信号；**仍没有图本身带来模型理解净增益的证据** |
| 图能否提高已生成摘要的可靠性？ | Redis 有窄正结果，但[冻结迁移](independent-transfer-development.md)中 xv6 路径筛选仅保留 8.53% 且仍有错误，Nginx 保留 55.19% 无观察错误却被普通树的 62.15% 超过；新的事实检查接口能拦截六条被原始 C 反驳的模型断言 | **稀疏路径筛选迁移失败；静态事实检查有局部工程用途**。仍没有完整摘要的准确率—信息覆盖净优势 |
| 摘要是否达到实用质量？ | 尚无独立专家标注的功能级自然语言摘要、证据充分性与漏报评价 | 不能声称自然语言摘要优于已有方法 |

## 迁移实验之后的下一项门槛

此前提出的冻结迁移实验已经执行并失败，不能继续写成尚待完成。下一项若继续投入，应在未用于开发的功能上预先标注完整摘要中的关键事实，比较源码摘要、传统程序分析事实加摘要、当前行为图检查摘要，同时评价正确性、遗漏、无信息断言及成本。在相同有用信息量下若不能减少错误，就放弃“图提高模型理解能力”的主张，将图后端保留为工程工具。原始失败和空结果全部保留。

直接给顺序关系、线性事件或对象版本图都没有修正整体错误；新 [生产验证器](../src/repo_summary/verified_behavior.py)因此把图留在后端，默认给模型短反例，具体因果轨迹按需查询。集成烟测见 [对象版本对照](object-version-comparison.md)：不同提示和模型输出下仍不稳定，不应把开发集信号当成端到端系统已成功。

四案例生成器已在两个大仓库功能的 1,008 个有限原始 C 输入上完成逐例核对，能产出带源码位置的受限交互证据；但等四案例模型对照仍无提升。下一轮若继续“模型理解增强”主张，应由模型先提出**具体功能断言**，图针对该断言主动寻找反证或明确无法验证的边界，再与等预算普通测试生成对照；之后才到此前未用于开发的仓库与自然语言事实标注。若图后端找不出传统测试找不到的有效反证，或净收益不及成本，应把论文主张转向“可审计的跨函数行为查询及其可靠性边界”，不要宣称智能体理解增强。

本轮进一步实现了**按字段、按源码行为路径的有界证书**：模型规则可以整份不正确，但局部路径规则仍可保留。这是系统价值的更可信方向，完整设计、对照和失败边界见 [路径分区核验](path-conditioned-summary-development.md)。它尚未把路径签名转成可读的输入条件；PostgreSQL 的留出错误表明，仅用分支序列遗漏了模拟回调产生的状态差异。下一阶段须在新的仓库/功能上预先冻结状态前提表示和对照，再检验是否真正降低错误摘要、保持有效覆盖，而不是继续只在两个开发任务上调分区。

后续实验修正了一个重要漏洞：若给留出输入直接使用其真实行为路径，行为图已经执行并得到答案，不能把这一步算作免费预测。现在输入树只根据已查询样本的路径预测留出路径；有限域表达式检查只在被路由到同一区域的输入之间寻找错误依赖。[新方法与验证](guarded-path-summary-development.md)表明第三个 Redis 功能上能筛选出较可靠的字段规则，但这属于**智能体输出的后端审查**，并不支持“模型内在理解已经增强”。新仓库、新功能、同风险—覆盖及自然语言摘要比较仍必需。
