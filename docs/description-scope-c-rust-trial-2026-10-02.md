# C/Rust 自动修复实验：2026-10-02 进展与审计

**状态更新（2026-10-03）：旧主线已停止，原型、请求/回复、分析脚本和原冻结文件已校验归档。** 本页保留实验结论；原版也在归档中。材料位置见[清理与归档](retired-description-experiments-2026-10-02.md)，后续要求见[重新选题交接](research-handoff-next-method-2026-10-02.md)。

本文记录实际开发过程，最终状态以各运行的 `results.json`、`analysis.json` 和 `disposition.json` 为准。最终决定已形成：停止扩展当前候选；具体证据见文末“完整结果与决定”。不会把未完成或评测失真的试验写成成功，也不会把一个候选失败说成整个方向被证明不可能。

## 本次检验的具体方法

对同一功能生成长描述和不超过 300 字符的短描述。用真实程序的开发输入检查两份描述：只将“长描述能支持正确回答，短描述不能”的行为作为局部修复目标。修复模型看到源码与这些开发反例，输出原文片段的替换。它不读取评测输入或答案。

强对照获得同一源码和全部开发错误/未知字段，直接重写短描述。普通源码自查作为第二个对照。三组共用初始描述、输出预算和接受条件；开发检查不允许破坏已正确字段或新增错误。补丁通过只意味着通过这些已观察输入。

方法的潜在价值只能是：利用阶段差异提供更准确、更节省的修复目标。**执行测试、给模型反例、局部替换或增加 Agent 角色，本身不构成这里的新贡献。**

## 数据确实来自什么

三个新项目、四个功能：Zephyr 环形消息缓冲取出；cJSON 对象替换；heapless 向量追加与插入。执行未修改的上游算法，C 用宿主宏兼容头，Rust 放宽旧 crate 的编译告警。154 个不同输入各运行两次，共 308 次观测一致；另有 104 个 C 输入通过 ASan/UBSan。

冻结 32 个开发输入、46 个评测输入。评测改变消息长度、JSON 键或向量容量，与开发输入不重合。选择按结果类别平衡，不代表自然使用分布。四个函数与助手设计的有限夹具也不代表整套操作系统或任意仓库的自动评审。

## 已经发现的实验问题

| 记录 | 事实 | 可得结论 |
|---|---|---|
| trial-v1 | 非思考读者把 cJSON 的 JSON 对象值误当成 C 结构体状态，源码控制失败 | 读者不能直接用于比较 |
| trial-v2 | 明确 JSON 值投影并开启思考后，16 个控制全通过；47 次调用自然完成，7/8 共同摘要超长 | 格式失败主导，不可比较方法 |
| trial-v3 | 反馈实际字数、最多两次共同重试后，仍只有 3/8 摘要有效；52 次调用完成 | 不能靠放宽预算或删除失败样本宣布有效 |
| trial-v3 的读者记录 | 同一段文字重复读取出现不同评分；两次回复耗尽输出预算 | 源码/空材料/表格控制通过，并不保证自然描述评分稳定 |
| format-probe-v1 | 相同的四份压缩请求换 Pro 生成器，输出 169/175/165/128 字符，4/4 合格 | 可以统一换更强生成器继续公平比较；这只是格式诊断 |
| trial-v4 | 三组统一使用 Pro 生成器；相同读者请求共用评分；运行前协议、源码和输入均记录哈希 | 56 次调用完成，8/8 最终文本与初始及反例基线相同；停止扩展此候选 |

trial-v3 中，Zephyr 同一描述两次评分相差 3/24 个字段；cJSON 同一描述一次因回复超限全为 unknown，另一次全部正确，另一份重复读取还有 4 个错误。这些差异必须记为评测问题，不能记成修复方法带来的改善或退化。

trial-v4 的请求复用消除了“完全相同文本获得不同组间得分”的混淆，但不能消除不同文本的模型理解误差。生成器和读者同属 Pro 还可能存在相关错误。未知项、错误项和响应失败继续分别保留。

## 预先固定的取舍规则

候选需要相对全部反例重写减少至少 20% 错误；每种语言正确覆盖下降不超过 5 个百分点；至少两个项目改善；生成与修复调用成本不超过 1.5 倍。实际研究调用和各组独立运行成本分开报告，评测调用不能隐藏。

零基线错误、差异由坏格式或读者失败主导、只改善单一函数都不算胜出。两次重复均无净收益、且不存在跨项目的错误—覆盖优势，则停止扩展这个“阶段差异筛选 + 局部修复”候选。停止投资候选并不等于证明所有行为条件研究不可能。

如果候选和反例基线输出完全相同，文本相同性可独立于读者评分检查；此时新增长描述检查只能增加成本，不能宣称准确性增益。该证据仍限于本批功能。

## 系统侧已经落地的修复

共用摘要和树标题曾把纯文本 `fd<0、fd>=NOFILE` 当作 HTML 标签剥掉。现已显式区分普通文本和 HTML，HTML 只解码一次；同类修复覆盖开发过程摘要。模块 digest 优先使用完整 `summary`，避免被早先截断的 `brief` 覆盖。

修复前后实例见 [确定性回归记录](../research/description_integrity/digest-plain-text-2026-10-02.json)。相关描述、报告、开发过程、PDF 与研究机制测试共 **350 项通过**，其中 13 项属于新实验机制；不是整个仓库测试，也不是模型准确率。中文字体与测试依赖保存在工作区外缓存，来源和哈希记入[验证记录](../research/description_integrity/validation-2026-10-02.json)。

这些修复防止已有文字被确定性处理破坏，但不证明原始模型描述正确。共用摘要的限长策略仍可能省略信息；此次没有声称获得端到端语义保证。实验候选尚未接入生产。

## 相关工作的约束

- [METAMON（2025）](https://arxiv.org/html/2502.02794v1) 已用回归测试捕捉程序行为，再用模型与变形查询检查文档一致性。真实执行加模型判断不能直接作为本项目的新颖性。
- [ReFEree（ACL 2026）](https://aclanthology.org/2026.acl-long.653/) 已研究结合依赖信息的分段代码摘要事实核验。分段检查和补依赖上下文也不够独特。
- [COVER（2026）](https://journals.sagepub.com/doi/10.3233/FAIA260737) 在自然语言约束建模中使用带类型的中间表示、求解器反例和局部修复。任务不同，但“结构化表示 + 反例 + 局部补丁”的通用架构已有先例。

因此，顶刊判断必须建立在可复现的新现象、可靠自动方法及跨系统收益上。当前资料不能支持“搭好这条链就能发顶刊”，也不能用工程修复的测试通过率替代论文效果。

## 完整结果与决定

**决定：停止扩展当前“阶段差异筛选 + 局部修复”候选，不将它作为顶刊主方法。** 这是针对已实现候选的淘汰决定；不是证明整个代码描述研究领域不可能。

trial-v4 自然完成，共 56 次真实调用、35 次相同读者请求复用。8 份共同摘要全部符合 300 字符上限。四个功能、两个重复中，候选最终文本 **8/8 与反例重写完全相同，也都与初始短描述相同**。所以没有任何项目获得额外输出收益；这个结论可直接比较文本，不依赖模型读者是否读对。

| 方法 | 生成与修复调用 | 对应总 token | 最终改变的样本 |
|---|---:|---:|---:|
| 源码自查 | 34 | 68,750 | 0/8 |
| 全部反例重写 | 29 | 67,765 | 0/8 |
| 阶段差异局部修复 | 37 | 103,490 | 0/8 |

表中给出每组独立运行所需的生成与检查成本，复用相同请求，排除控制与最终评测；不是把共享调用重复加到实际账单。候选调用多 27.6%，token 多 52.7%；token 不等于真实人民币费用。各组的修复轮数和文字预算相同，实际计算用量分别报告，没有声称精确相同的 token 消耗。

两次局部修复尝试均在 cJSON：一次被开发回归检查拒绝，一次违反 300 字符上限。其余六份未产生修复目标。其中一份 cJSON 的全部 16 个“丢失字段”由读者回复超限后记为 unknown 触发，不能称为真实的 16 个语义损失。这暴露出当前实现把评测失败与材料不足混在一起的问题，是淘汰实现的可靠性依据之一。

原始代理分数四组都是 133 个正确、17 个错误、34 个未知，共 184 个字段判断。**这些不是核实后的描述错误率**：4 次读者请求耗尽输出预算，且已有读者误解明确文字的证据。只用它们报告运行表现，不能写成“描述准确率 72.3%”或进行虚假的独立样本显著性检验。决定的主要依据是最终文本相同且成本更高。

另对首个回归拒绝实例做了事后选取的 9 次单输入复读：源码 3/3 正确，原文 2/3 正确，补丁文本 0/3 正确。预先规定的“源码和原文均 3/3 正确、补丁均错误”稳定伤害条件未通过，因此**不能把原先拒绝全部解释为补丁造成的稳定语义退化**。这次复读是读者诊断，不是新的独立留出实验，也不是方法成功案例。

本目录累计 184 次 API 调用、503,586 token，包括控制失败、超长输出及诊断；收到回复不等于得到有效结果。旧 Python 先导与已归档实验另计。完整[决定及证据哈希](../research/scope_repair/decision.json)、[分析](../research/scope_repair/trial-v4/analysis.json)、[调用记录](../research/scope_repair/ledger.json)均可复查。

当前能支持的是：系统中的确定性破坏已修复；这个自动修复候选没有达到继续投入门槛。尚不支持可投稿 TSE/TOSEM 的新方法，也不支持把更广泛的行为条件研究判为不可能。不会继续靠更换 Agent 名称、增加角色或选择有利样本维持这个候选。
