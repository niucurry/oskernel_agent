# 公开移植仓库能否提供自然修改真值

本轮实际实现并运行了自然样本适用性原型：[natural_upstream_review](../research/natural_upstream_review/README.md)。它检验共享 OS 框架扣除问题能否从公开项目取得独立真值，允许实证研究贡献，但不把已有精确来源检查重新包装成新算法，也不恢复已停止的条件/摘要研究。

选择来自比赛官方参考页的三个公开移植项目：la-seL4、xv6-loongarch-exp、rCoreloongArch，与固定的 seL4、xv6-riscv、rCore-Tutorial-v3 上游分支配对。当前公开头不是经过认证的参赛提交。事前冻结项目、分支、预算、祖先适用条件、每项目至少五个源码变更函数和至少两个支持项目的阈值。源码变化不能直接视为团队新增工作：它也可能来自上游版本漂移。因此先要求选定分支存在唯一完整的 Git 共同祖先，再谈局部改动标签。

六个完整、非浅克隆的分支元数据实际获取成功，共 8,564,250 字节。九条主测 Git 命令表明三个项目对都没有共同祖先。不能以猜测的最新上游、名称相近的仓库或参赛说明替代祖先证据。原型依协议停止，**自然源码 blob、函数配对、分类器重放、模型调用、构建和启动均为零**；既不能算自然效果成功，也不能说没观察到源码差异就证明没有评审问题。

为防止将实现错误当负结果，另冻结独立图验证：两个本地对象库中的已知分歧分支通过相同 alternate-object 查询准确找到共同根；六个实际分支的非浅状态和完整连通性检查通过，各对根提交集合互不相交。验证阶段 39 条 Git 命令，未切换实际分支或修改主实验结果。这证明当前固定分支无法提供所需的共同历史标签；不排除源码复制关系、别的分支或源码版本推断途径。

原协议及事前采样修订均保留：修订发生于元数据获取后、任何祖先或源码测量之前，把预算用于继承文件中的已修改路径；未改变假设、阈值、项目或预算。因为三个样本都未进入源码阶段，修订未影响结果。若有适用样本，独立 Pygments 词法标签和生产 Tree-sitter 来源检查分别计算，合成重放会明确标注，不能当真实跨队关系；这些后续代码此次未运行。

文献检索也限制了新颖性：[CONPLAG](https://arxiv.org/pdf/2303.10763)已经研究比赛模板影响，[JPlag](https://github.com/jplag/JPlag)已有基础代码扣除，[SourcererCC](https://arxiv.org/abs/1512.06448)已有源码 token 克隆方法，[CENTRIS](https://seulbae-security.github.io/pubs/centris-icse21.pdf)已有修改和嵌套 OSS 复用识别。它们是后续强基线与问题边界，不能把“存在共享代码”当新发现。此次没有安装或运行这些外部检测器；数据适用性门槛失败后，不应继续消耗预算并虚构比较效果。

获取用时约 12.56904 秒墙钟 / 0.726282 秒子进程 CPU；主检测 0.0679271 / 0.044394 秒；独立图验证 0.326788 / 0.307294 秒。预备、导入和哈希另计；没有性能优势主张。历史 392 个实际运行单元没有增加。

结论：停止这三个固定分支的“仅凭 Git 祖先构造自然局部修改标签”路线，保留原型、原始命令及负结果；不外推整个上游研究不可行，也不宣称系统来源修复已取得自然评审效果。总体选题目标仍在进行。已向用户询问可读取的正式提交、当时上游版本和运行日志目录，等待期间继续独立验证；缺少这些证据不会被改写成论文成功。
