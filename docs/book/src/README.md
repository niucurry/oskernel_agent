# 介绍

OS Kernel Review Agent 是面向**全国大学生操作系统比赛评委**的内核作品分析系统。它从参赛作品的源码、Git 历史和历年作品库中，自动生成四份**参赛队无法修改**的正式报告，用于缩小人工复核范围。

> 系统只负责指出"哪里值得人再看一眼"，不自动作出抄袭、违规或获奖结论。

## 四份正式报告

| 报告 | 文件 | 回答什么问题 |
|---|---|---|
| 一页摘要 | `summary.pdf` | 这支队伍整体情况如何，有哪些必须先看的问题 |
| 作品描述 | `description.html` | 代码是不是真的能跑、有没有硬编码作弊、各内核模块完成度如何 |
| 开发过程 | `development.html` | 提交历史有没有异常、开发分了几个阶段、哪些提交可疑 |
| 同源对比 | `comparison.html` | 与最接近的历史作品在模块／函数／文件级有哪些同源证据 |

## 设计原则

**AI 只做判断，事实由程序复算。** 提交次数、代码变更行数、函数切分、文件行号等一切可计算的事实，全部由程序从仓库直接得出，AI 不参与；AI 只负责在给定事实上做判断和归纳。

**每条结论都必须能回到证据。** 报告里的每个提交、函数、文件、行号都能点开回到原始位置；证据链断了就拒绝交付。

**不合格就不出报告。** AI 调用失败、结构化输出无效、复核未覆盖全部候选、报告语言不达标时，系统直接判定交付失败，绝不带病出报告。

## 质量门禁

- 严重问题和模块不因版面配额被静默截断；
- 公共上游、第三方库、比赛基线、ABI 受限实现和机械误报不得混入同源比例；
- 召回库或索引代际不完整时，拒绝生成"未检出相似"结论；
- 硬编码候选必须逐条经 AI 复核，缺少事实或证据链接无效时拒绝交付；
- 正式报告完全由工具生成，参赛队无需且不得后处理 HTML/PDF。

## 技术要点

- **Python 3.11+**，`src` 布局，单一命名空间 `oskernel_agent`；
- **源码解析**：Universal Ctags 符号表 + tree-sitter（C/Rust），可选 LSP（rust-analyzer / clangd）语义引擎；
- **查重**：CodeT5p 嵌入 + FAISS HNSW 向量检索 + SimHash（特征／结构两代）+ SQLite FTS5 全文；
- **报告**：HTML（内联 Tailwind + ECharts）与 reportlab 生成的 PDF；
- **前端**：Vue 3 + Vite + Express + sql.js 控制台；
- **CI**：GitHub Actions（单元测试、前端构建、召回评测回归）。
