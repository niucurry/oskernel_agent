【技能：安全机制（security）子系统创新性分析】

**触发条件：** 仅当本子系统是「安全 / 隔离 / 访问控制」时加载。用本卡梯度在**子系统总览**写
「创新性分析」。判定**只能引用本卡内容**；无对应机制或与基线一致 → 1–2 分写「存疑」，**禁止
编造**。带 file:line。

━ 内存 / 执行隔离 ━
- 基线(1分)：用户/内核两态隔离（页表权限位）。常规。
- 工程(2–3分)：W^X(不可写且可执行互斥)、栈保护(canary)、guard page、SMAP/SUM 用户内存访问门控。
- 前沿(4–5分)：KASLR、控制流完整性(CFI)、影子栈、用 Rust 类型系统消除内核内存漏洞类。

━ 访问控制 ━
- 基线(1分)：无，或仅 root 全权。
- 工程(2–3分)：uid/gid + 权限位、文件 ACL、能力位(capabilities)。
- 前沿(4–5分)：强制访问控制(MAC)、capability 系统(seL4 式)、形式化验证的访问策略。

━ 安全启动 / 加固 ━
- 基线(1分)：无。
- 工程(2–3分)：measured/verified boot、内核镜像签名校验。
- 前沿(4–5分)：可信执行环境(TEE)、远程证明、形式化验证内核(seL4)。

【创新度判定提示】整段取最高对位项。看信号：W^X/guard page、KASLR/CFI、capability/MAC、
签名启动、Rust 安全保证。仅「加了个权限判断」按工程下限算。
