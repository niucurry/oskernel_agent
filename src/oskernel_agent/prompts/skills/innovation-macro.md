【技能：宏 / 元编程（macro）子系统创新性分析】

**触发条件：** 仅当本子系统主要是「宏 / 元编程 / 代码生成」时加载。用本卡梯度在**子系统总览**
写「创新性分析」。判定**只能引用本卡内容**；无对应机制或与基线一致 → 1–2 分写「存疑」，**禁止
编造**。带 file:line。

━ 声明宏 / 样板消除 ━
- 基线(1分)：手写重复代码，少量简单 `macro_rules!`。常规。
- 工程(2–3分)：声明宏生成 syscall 表/寄存器定义/中断向量表，减少样板与出错面。
- 前沿(4–5分)：复杂声明宏 DSL（如配置驱动生成）。

━ 过程宏 / 代码生成 ━
- 基线(1分)：无过程宏。
- 工程(2–3分)：derive/attribute 过程宏自动生成 trait 实现、设备/驱动注册。
- 前沿(4–5分)：过程宏构建领域 DSL、编译期生成状态机/页表布局。

━ 编译期检查 / 类型状态 ━
- 基线(1分)：纯运行时检查。
- 工程(2–3分)：const 断言、类型状态(typestate)保证寄存器访问/状态机合法。
- 前沿(4–5分)：编译期消除一类运行时错误（如非法外设访问不可编译）。

【创新度判定提示】整段取最高对位项。看信号：宏生成的表/注册、过程宏 derive、const 断言、
typestate。仅「一两个 println 宏」不加分。
