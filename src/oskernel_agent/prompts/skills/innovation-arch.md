【技能：体系结构 / 硬件抽象（arch）子系统创新性分析】

**触发条件：** 仅当本子系统是「硬件抽象 / 体系结构 / 启动引导」时加载。用本卡梯度在**子系统
总览**写一节「创新性分析」（不写进模块详细）。判定**只能引用本卡内容**；无对应机制或与教学
基线一致 → 定 1–2 分写「与标准做法一致 / 无法对标前沿，存疑」，**禁止编造**。带 file:line。

━ 启动引导 ━
- 基线(1分)：固定 entry 清 bss 跳 rust_main，单核启动。rCore/xv6 常规。
- 工程(2–3分)：多阶段 boot、SBI/OpenSBI 调用封装、设备树(FDT)解析传参、多核 hart 唤醒。
- 前沿(4–5分)：安全启动链(measured boot)、kexec、运行时重定位启动。

━ CPU / 特权级 / HAL 抽象 ━
- 基线(1分)：直接读写 CSR、架构相关代码散落各处。
- 工程(2–3分)：HAL trait 封装架构相关(axhal 风格)、per-CPU 数据、特权级切换封装。
- 前沿(4–5分)：多架构统一抽象(RISC-V/LoongArch/x86/aarch64 同一套上层)、运行时特性探测。

━ 缓存 / 内存屏障 ━
- 基线(1分)：无显式屏障/缓存维护。
- 工程(2–3分)：fence/cache flush 封装、DMA 一致性维护、弱内存序正确处理。
- 前沿(4–5分)：屏障最小化优化、弱内存模型相关的可验证封装。

━ 链接 / 重定位 ━
- 基线(1分)：固定地址链接脚本。
- 工程(2–3分)：PIE/重定位、内核可重定位加载。
- 前沿(4–5分)：KASLR 内核地址随机化。

【创新度判定提示】整段取最高对位项。看信号：FDT 解析、多核唤醒、HAL trait、多架构、per-CPU、
屏障/缓存维护、重定位/KASLR。仅「改了 entry 地址常量」不加分。
