【技能：系统调用层（syscall）子系统创新性分析】

**触发条件：** 仅当本子系统是「系统调用入口/ABI」且要评创新时加载（评覆盖率仍用
`syscall-coverage`，二者不同）。用本卡梯度在**子系统总览**写一节「创新性分析」。判定**只能
引用本卡内容**；无对应机制或与基线一致 → 1–2 分写「存疑」，**禁止编造**。带 file:line。

━ 分发机制 ━
- 基线(1分)：`match syscall_id` 大表逐个手写。rCore/xv6 常规。
- 工程(2–3分)：表驱动分发(函数指针表)、统一参数校验、errno 规范返回。
- 前沿(4–5分)：快速系统调用路径、批量 syscall、io_uring 式异步提交免每次陷入。

━ ABI / 兼容性 ━
- 基线(1分)：自定义少量调用，非标准号。
- 工程(2–3分)：POSIX 子集广覆盖、Linux 兼容 ABI(号/语义对齐)、多个 ABI 入口。
- 前沿(4–5分)：vDSO 免陷入调用(gettimeofday 等)、64/32 位多 ABI 共存。

━ 安全 / 健壮性 ━
- 基线(1分)：不校验用户指针。
- 工程(2–3分)：用户指针/长度校验、copy_from/to_user 封装、seccomp 式过滤。
- 前沿(4–5分)：能力(capability)化系统调用、细粒度 syscall 过滤策略。

【创新度判定提示】整段取最高对位项。看信号：函数指针分发表、POSIX/Linux 兼容广度、
用户指针校验封装、vDSO、异步/批量。仅「多加几个 syscall case」按覆盖率算、不计创新。
